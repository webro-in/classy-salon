# DEPLOYMENT — Static Website

The production site is a folder of **prebuilt HTML files + hashed assets**. No server, functions, database or secrets.

## 1. What the build produces
```
dist/
├── index.html                 # Home, fully rendered
├── about/index.html
├── services/index.html
├── gallery/index.html
├── reviews/index.html
├── contact/index.html
├── privacy/index.html
├── terms/index.html
├── 404.html
├── assets/*.js|css|avif|webp  # hashed, immutable
├── media/...  logo/...  icons/...
├── sitemap.xml
└── robots.txt
```
Generated by `vite-react-ssg` (see DRD §3). `scripts/verify-dist.ts` fails the build if any file is missing or lacks its title, meta description, canonical, `<h1>` and body content.

## 2. Commands

```bash
npm install
npm run dev               # development: Vite dev server, no content checks
npm run build             # PREVIEW build: placeholders allowed, missing data reported only
npm run build:production  # RELEASE build: fails until all required client content is verified
npm run preview           # serve dist/ exactly like a static host (clean URLs, real 404)
npm run typecheck && npm run lint && npm test && npm run e2e
```

### Build modes

| Command | Mode | Missing client data | Use it for |
|---|---|---|---|
| `npm run dev` | Development | Never checked. Placeholders and dashed `[CLIENT DATA REQUIRED]` markers show | Day-to-day work |
| `npm run build` | Preview | Reported, **never fatal**. Placeholders, markers and `/styleguide` included | Client previews, staging, QA, e2e |
| `npm run build:production` | Production release | **Fails the build** | The final live release |
| `npm run preview` | n/a | n/a | Serves `dist/` like a static host on :4173 |

`npm run build:production` sets `VITE_STRICT_CONTENT=true` and fails on any of:

- pending business/contact data (phone, WhatsApp, email, hours, rating, story, legal name, second Instagram)
- fake-looking contact data (e.g. `+91XXXXXXXXXX`, `test@example.com`)
- unconfirmed service names (`labelStatus: needs-confirmation`) or missing service descriptions
- required media still placeholders, missing logo files (optional slots such as per-service images and the hero video may stay empty)
- reference-site / competitor wording, partnership claims, unapproved names or filler text in `content/`
- a missing production `VITE_SITE_URL`
- and, as a second check on the rendered HTML: any content marker, placeholder media or unbuilt section scaffold, or the `/styleguide` page

Run `npm run content:check` at any time to see what is still needed (report only).
`npm run content:check:strict` runs just the release content gate.

Note: `npm run dev` renders on the client for speed. Validate HTML/SEO with `build` + `preview`.

## 3. Environment (`.env.example`)
```
VITE_SITE_URL=https://www.example.com   # [CLIENT DATA REQUIRED: domain], canonical base
VITE_ANALYTICS_PROVIDER=none            # none | plausible | ga4
VITE_ANALYTICS_ID=
VITE_STRICT_CONTENT=false               # true for production builds: unresolved content fails the build, removes /styleguide and dev markers
```

## 4. Vercel (recommended)
- Framework preset: **Other**. Output `dist`.
- **Production** environment build command: `npm run build:production`.
- **Preview** deployments build command: `npm run build` (placeholders visible for client review).
- Production env: `VITE_SITE_URL` (the build command sets strict mode itself).
- `vercel.json`:
  ```json
  {
    "cleanUrls": true,
    "trailingSlash": false,
    "headers": [
      { "source": "/assets/(.*)", "headers": [{ "key": "Cache-Control", "value": "public, max-age=31536000, immutable" }] },
      { "source": "/(.*).html", "headers": [{ "key": "Cache-Control", "value": "public, max-age=0, must-revalidate" }] }
    ]
  }
  ```
- `/about` serves `dist/about/index.html` directly. **No SPA rewrite to `/index.html`**: unknown paths must return `404.html` with a real 404 status. Do not add a catch-all redirect to Home.
- `npm run preview` (scripts/serve-static.ts) mirrors this: unknown paths and `/404` itself are served from `404.html` with status 404. On hosts with clean URLs, `/404` may be served with status 200; it is `noindex` and not linked anywhere.

## 5. Alternatives
Netlify (publish `dist`, `404.html` auto-served), Cloudflare Pages (same), or any static host/S3+CDN that serves `dir/index.html` and a custom 404.

## 6. Go-live checklist
1. `npm run build:production` passes. It fails while any required item is missing, including: legal business name, legal effective date and governing law (`content/legal.json`), approved client reviews, brand logo files, consent for people in photos, ⚑ service labels/descriptions, salon story/philosophy, production domain; or if analytics are enabled without updating the Privacy Policy. In strict mode `verify-dist` also rejects any remaining `[… REQUIRED]` marker, placeholder media or `/styleguide`.
1a. The Privacy Policy and Terms have been reviewed by the client or their adviser (the wording is a draft, not legal advice).
2. Domain + HTTPS, a single canonical host (www or apex) with redirects.
3. Submit `sitemap.xml` to Search Console. Test share previews (WhatsApp, Facebook debugger).
4. Add the URL to the Google Business Profile and both Instagram bios.
5. Re-verify the rating monthly in `content/business.json`.

## Client preview on Vercel (staging)

`npm run build:staging` builds a clean client-preview site: no developer markers,
no styleguide, `noindex, nofollow` on every page (plus an `X-Robots-Tag` header
and `robots.txt: Disallow: /`). The production release gate is unchanged:
`npm run build:production` still fails until every client item is verified.

`vercel.json` runs `npm ci` + `npm run build:staging` and serves `dist/`.
Canonical/OG URLs use `VITE_SITE_URL`, or Vercel's project address when unset.

Setup (once): vercel.com → Add New → Project → import `webro-in/classy-salon`
→ Deploy (settings come from `vercel.json`). Every `git push` to `main` redeploys.

Going live for real: finish the release blockers, set `VITE_SITE_URL` to the
domain, change `buildCommand` in `vercel.json` to `npm run build:production`,
remove the `X-Robots-Tag` header, and add the domain in Vercel → Domains.
